# CLAUDE.md

Project Copper is a stealth RPG built with React 19, Three.js, Zustand, and TypeScript (Vite). It has two views of the same shift: a 2.5D diorama through a fixed isometric camera, and first person.

## Commands

- `npm run check` runs lint, typecheck, unit tests, and build. Run it before every commit.
- `npm test` runs Vitest. Core and state tests run in node; UI tests opt into jsdom with a `/** @vitest-environment jsdom */` docblock.
- `npm run e2e` runs Playwright: a desktop keyboard run (`game.spec.ts`), an emulated iPhone touch run in landscape (`mobile.spec.ts`), and the one-file build on an upright iPhone inside a stand-in for its host frame (`artifact.spec.ts`). In cloud containers, set `PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium`.
- `npm run build:artifact` writes `dist-artifact/project-copper.html`, the whole game as one page fragment for publishing as a Claude artifact (the playable link). After a change the player should see, rebuild and republish it to the same artifact.
- `npm run format` runs Prettier. CI runs `format:check`.

## Architecture rules (enforced by ESLint)

`ui → game → state → core`. Imports only point toward `core`.

- `src/core` is pure TypeScript: no Three.js, React, or Zustand. All game rules live here, and `ShiftSession` is the single source of truth for a shift.
- `src/state` holds Zustand stores and may import only `core`.
- `src/game` holds the Three.js rendering and input. `GameEngine` stays thin: it feeds input to the session and draws its state through whichever camera is in use. Don't put rules here (line of sight, cover and light math live in `core/systems`).
- `src/ui` is React. It never imports `three`; it mounts `@game/GameView`.

## Conventions

- Content is data. Characters, fixtures, upgrades, abilities, student personalities, teachers, and levels live in `core/content/*` and `core/level/levels/*`, keyed by string ids.
- The school map is generated by `scripts/gen-school-map.py` (edit the script, then regenerate). Mount fixtures on north or east walls where possible; the camera looks from the south-west, so those are the faces you see.
- Technical fixtures and security doors use a `Requirement` (gear tier and/or worker level); `systems/requirements.ts` turns an unmet one into the prompt's reason.
- NPC brains are pure functions in `core/ai/*`: the boss plans rounds from `npcPlaces.ts` patrol points, weighted by staleness and per-room heat. Reports, evidence and noises are `Stimulus` values with a priority. The head custodian works `cleaningJobs`; anyone who calls in a report hands the boss a `report` stimulus.
- Scrap outcomes (botched / rough / clean / bonus) come from `systems/scrapping.ts`: a roll shifted by `efficiency` (gear, Craftsman skills, the worker's repair on that fixture). Tune the bands in `BALANCE.scrapping.outcome`.
- Balance numbers belong only in `core/content/balance.ts`.
- New mechanics get unit tests in `core`. The pattern to copy is `ShiftSession.test.ts` driving a tiny ASCII map from `core/test/helpers.ts`.
- Persisted save changes need a `SAVE_VERSION` bump plus a `migrateCareer` step. Preferences that aren't progress (the camera) live in `state/settingsStore` instead, with their own key and `migrateSettings`.
- Gear and skills share one `Modifiers` shape; `deriveStats` folds them into `EffectiveStats`. Add a modifier there rather than special-casing an item id in the session.
- Every control must work by touch as well as keyboard. Touch UI writes to `state/virtualInput`; `InputController` merges it with the keys. Anything a thumb presses is at least 44px, text at least 11px, and anything held lets go when the page is hidden (`useLetGoWhenAway`): a finger lifted in another app is never reported.
- Phones are a first-class target. Anything pinned to a screen edge uses the `--safe-*` properties from `theme.css`, never `env()` directly (the artifact build zeroes the ones its host already pads). No `backdrop-filter` over the live 3D view. The game must survive being backgrounded: `GameView` replaces the engine around the same `ShiftSession` when the WebGL context is lost, so state worth keeping lives in the session, not the engine.
- The view (`ViewMode` in `state/settingsStore`) switches at any time: `V`, the HUD's eye button, the pause menu. Both views must keep working: anything only one of them shows goes through `World.setFirstPerson`, and each has its own grade in `render/looks.ts` (including how far exposure adapts to a dark room).
- First person gives core a look direction: `PlayerInput.aim` (facing, gadget throws and which target you reach for follow it). Mouse look is `input/LookController` (pointer lock, drag as a fallback); the arrow keys turn too, and touch drags the HUD's look zone. The first-person math (`render/lookMath.ts`) is pure and unit-tested.
- Phones get their own compact HUD (`ui/hud/TouchBar` chips plus `TouchControls`); the desktop cards stay in `Hud.tsx`. Both read the shift through the shared selectors in `ui/hud/hooks.ts`.
- Models are built procedurally in `game/render/models/` (fixtures, props, set pieces, wall decor, characters), keyed by content id, so placeholder art can be swapped for glTF later. Build each one to its content `footprint`, which is also its hitbox. Lit materials go through `MaterialKit` so they pick up baked light and fog of war; a material's `emissive` is drawn brighter than white (it blooms) and isn't dimmed by a dark room.
- Light is baked, not computed per frame: `render/lighting.ts` lays out lamps, glowing props and door spill from the level (pure, unit-tested), and `LightBaker` draws them into the light map every material samples. Core's room `light` level stays the rule; the bake only spreads it around the room. Tune lamps per room kind in `STYLE` there.
- The floor is `render/floorTexture.ts`: one repeating layer per room kind (colour, relief, gloss) plus a paint map for what doesn't repeat. A new `RoomKind` needs an entry in each table there, in `FLOORS` and in `lighting.ts`.
- Post-processing is `render/post/PostFX.ts` (HDR scene, ambient occlusion, bloom, grade, FXAA). `QualityGovernor` decides how much of it a device gets; add any costly effect to its ladders (`QUALITY` for computers, `PHONE_QUALITY` for phones, which give up draw calls before pixels) rather than switching it on unconditionally. A lower level should look plainer, not darker: when a level drops something that also lit the scene (the environment map), `world.ts` makes up the light. The governor judges the frame rate against the screen's real refresh rate (`state/displayRate`, measured in the menus and while paused), so a phone capped at 30 isn't treated as slow.
- Markers and effects drawn over the world (sprites, cones, rings) take `asOverlay` on their material and `onOverlay` on their object, so ambient occlusion and the floor's reflection leave them alone.
- Static scenery is merged by `game/render/batching.ts` to keep draw calls low on phones: per room, welded and indexed, with every plain kit material folded into one (`MaterialKit.mixed()`, which reads colour, roughness, metalness and faceting from each vertex). Give a model a plain `kit.get(...)` material unless it truly needs a texture, glow or transparency: each of those is another draw call per room. Shadows are drawn only for what the top-down view shows (`render/shadowFit.ts`). Anything that moves (doors, characters, effects) stays out of the batch. First person only draws rooms it can see into (`render/occlusion.ts`), so new scenery belongs in a batch or registers itself for culling in `world.ts`.
- Characters share one jointed rig (`buildCharacter` plus a `RigSpec` outfit). `game/render/gait.ts` animates it from measured ground speed; the gait math is pure and unit-tested.
- Path aliases: `@core/*`, `@state/*`, `@game/*`, `@ui/*`.
- `?debug` exposes `window.__copper.session` for e2e tests and manual tinkering, plus `view()` (camera and look direction) and `quality(n)` (hold one quality level).
